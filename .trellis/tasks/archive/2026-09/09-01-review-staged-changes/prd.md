# 审核并修复当前暂存代码变更

## Goal

审核当前暂存变更并修复已确认问题，确保重试任务在取消异常、超时和并发终态竞争下稳定结束，同时补强页面去重测试并清理生成型构建产物。

## Background

- 当前暂存区包含 `src/server/task-manager.ts`、两份测试文件和一份 Android 构建报告。
- 核心代码新增重试任务看门狗、重试停止时的立即终态化，以及 Runner 返回后的重复终态保护。
- 测试新增重试超时、停止重试和失败页面去重覆盖，并调整结果页文案断言。
- 审核确认取消钩子可让停止或超时流程永久等待，`finalize()` 存在重复完成通知窗口，页面去重测试无法捕获核心回归。

## Requirements

- 审核范围覆盖当前全部暂存变更及其直接依赖的现有实现。
- 从任务状态转换、异步竞争、资源清理、持久化、监听器通知和重试来源锁定等维度检查行为正确性。
- 检查新增测试能否独立捕获目标回归，并识别仍缺失的重要边界场景。
- 检查 Android 构建报告进入暂存区是否符合仓库提交约定。
- 每条有效问题按严重程度排序，并提供文件与行号、触发条件和影响说明。
- 重试超时到达后立即取得失败终态所有权；Runner 取消钩子的挂起或失败只影响诊断日志。
- 人工停止重试后立即取得取消终态所有权，并保持 Runner 取消为尽力操作。
- 同一任务的并发终态请求共享一个提交过程，只持久化一次并通知监听器一次。
- 状态写入失败只影响当前保存操作，后续保存可以重新执行。
- 页面重试目标的去重逻辑由可独立测试的纯函数承载，结果页复用该函数。
- 从版本跟踪中移除 Android 自动生成的构建报告，并忽略示例工程的 `android/build/` 目录。

## Out of Scope

- 审核暂存范围以外且与本次行为无直接依赖的模块。
- 修改 Runner SDK 公共接口、HTTP API 或结果协议。
- 提交、推送或发布变更。

## Acceptance Criteria

- [x] 完整阅读暂存差异及任务管理器相关调用链。
- [x] 运行与变更直接相关的自动化测试和必要的类型检查。
- [x] 所有高、中优先级结论均由代码路径或可复现测试支撑。
- [x] 审核结果按严重程度列出并附准确文件行号；无有效问题时明确说明残余测试风险。
- [x] 修复保留用户现有暂存代码的原始行为与意图。
- [x] `runner.cancel()` 抛错或永久挂起时，重试停止仍及时返回 `cancelled`，超时仍及时进入 `failed`。
- [x] 看门狗、人工停止和 Runner 返回交叠时，任务只产生一次完成通知并保持首个终态。
- [x] 页面去重测试直接断言唯一 `targetPages`，删除去重逻辑会导致测试失败。
- [x] Gradle 构建报告退出版本跟踪，后续构建不会产生该路径差异。
- [x] lint、类型检查、相关测试与全量测试通过。
