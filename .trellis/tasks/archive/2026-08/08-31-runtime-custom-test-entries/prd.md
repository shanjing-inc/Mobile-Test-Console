# 执行页自定义测试入口与命令预览

## Goal

让用户在“执行测试”工作区直接理解和扩展项目的测试入口：预制入口继续可用，用户可以添加项目自己的测试命令，并在启动前确认当前入口最终调用的命令。

## Background

- 当前执行页的测试入口来自运行时 `snapshot.tests`，预制入口与 `mobile-test.entries.json` 中的自定义入口已经能够合并执行。
- `PublicTestDefinition` 只包含入口元数据和参数定义，执行页无法读取命令模板或解析后的命令。
- 现有“添加测试命令”采用五步引导，要求用户理解测试 ID、运行目标、结构化命令、参数和页面重试；截图反馈表明常用场景的操作成本过高。
- 用户主要在执行测试时选择入口，因此添加入口与命令确认需要进入这一工作流。

## Requirements

### R1. 统一测试入口

- 执行页继续展示 `mobile-test.config.cjs` 中的预制入口。
- 用户添加的自定义入口与预制入口进入同一个测试入口选择控件。
- 每个入口使用“预制”或“自定义”标识来源，帮助用户确认维护边界。
- 项目可以在 `mobile-test.config.cjs` 中为已有测试脚本声明业务化名称和用途；SaaS 小程序提供“员工取件码排序验证”预制入口，调用 `pnpm test:e2e:pickup-code-sort`。

### R2. 执行页添加自定义命令

- 小程序执行页提供“添加自定义命令”操作。
- 自定义命令保存为项目级持久入口，后续进入项目的用户可以持续选择和复用。
- 默认界面使用单页快速添加，只要求填写“显示名称”和“命令”；说明为可选字段。
- 命令使用用户熟悉的单行形式，例如 `pnpm test:e2e:pickup-code-sort`；系统解析为已有 executable/args 结构后保存。
- 系统根据命令生成稳定测试 ID，并默认选中项目声明的全部运行目标；单目标项目直接使用该目标。
- 测试类型默认使用“通用测试”，业务分类默认使用“自定义测试”。
- 工作目录、环境变量、运行目标、测试类型、业务分类、参数和页面重试放入“高级设置”折叠区。
- 命令解析支持空格、单引号和双引号参数；管道、重定向、命令连接和变量展开等复合 shell 语法给出明确错误。
- 保存按钮在当前页完成预览与写入；失败保留用户输入并显示具体字段错误，成功后关闭弹窗并选中新入口。
- 保存继续使用 `mobile-test.entries.json`、preview/apply、计划过期校验、路径边界、原子替换和备份机制。
- 保存成功后立即刷新执行页的测试入口列表并选中新入口。

### R3. 当前命令预览

- 选择测试入口后展示该入口实际使用的命令。
- 命令信息显示在测试入口右侧的现有说明区域。
- 命令预览随运行目标和测试参数变化而更新。
- 选择测试入口后立即预览命令：尚未勾选运行目标时使用该入口支持的全部已配置目标；勾选后使用实际选择范围。
- 入口只支持一个已配置运行目标时自动勾选该目标；多目标入口保留用户显式选择。
- 启动测试成功后保留当前运行目标选择，便于持续确认命令和重复执行。
- 当前只选择一个运行目标时，右侧说明区域直接展示该目标的完整命令。
- 当前选择多个运行目标时，右侧说明区域展示命令数量和“查看详情”入口；点击后在当前页弹窗按运行目标逐条展示完整命令。
- 展示 executable、按顺序排列的 args、最终 cwd 和环境变量名称。
- 环境变量敏感值脱敏；预览过程只解析命令，不执行测试。
- `task.id`、`task.runId` 等启动时生成的值使用明确占位符展示。
- 命令无法解析时展示具体原因，并阻止使用无效命令启动测试。

### R4. 兼容性

- 现有预制入口、任务启动请求、Runner 和 Result Bundle 行为保持兼容。
- “添加自定义命令”只出现在“执行测试”工作区；项目概览保持接入状态与存储管理职责。

## Acceptance Criteria

- [x] 小程序执行页同时展示预制入口与用户自定义入口，并标识各自来源。
- [x] SaaS 小程序执行页展示“员工取件码排序验证”预制入口，说明其验证首屏、跨页累计和刷新后的三段数字排序，并预览完整命令 `pnpm test:e2e:pickup-code-sort`。
- [x] 用户可以从执行页打开添加流程，保存后新入口立即出现在当前选择控件中并被选中。
- [x] 项目概览不展示“添加测试命令”操作，避免形成重复入口。
- [x] 选择任意预制入口或自定义入口后，可以看到 executable、args、cwd 和脱敏后的 env。
- [x] 切换运行目标或修改参数后，命令预览反映最终解析值。
- [x] 单目标直接展示完整命令；多目标展示摘要，并可在当前页弹窗查看每个目标的完整命令。
- [x] 命令预览不会执行测试命令；解析失败时启动按钮不可用并显示错误。
- [x] 预制入口继续由项目维护 `mobile-test.config.cjs`，自定义入口继续安全写入 `mobile-test.entries.json`。
- [x] 服务端契约、执行页交互、窄屏布局和兼容加载具备回归测试。
- [x] 打开“添加自定义命令”后，首屏只展示显示名称、单行命令、可选说明和“高级设置”。
- [x] 输入“员工取件码排序验证”与 `pnpm test:e2e:pickup-code-sort` 后可以直接保存，系统自动生成 ID、结构化命令和默认目标。
- [x] 引号参数可以正确解析；复合 shell 语法显示明确错误并保持表单内容。
- [x] 高级设置继续支持目标、类型、业务分类、工作目录、环境变量、参数和页面重试。
- [x] 保存仍经过服务端预览计划与原子写入，成功后新入口立即被选中。
- [x] 桌面和 `390x844` 下快速表单无横向溢出，保存操作始终可见。
- [x] 未勾选运行目标时按入口支持范围显示命令；单目标入口自动勾选，多目标入口可继续调整。
- [x] 启动测试后运行目标选择保持不变，命令预览持续可见并与下一次实际运行一致。

## Out of Scope

- 自动扫描、猜测或推荐项目测试命令。
- 在浏览器中提供任意 shell 终端。
- 执行管道、重定向、命令连接、变量展开或其他复合 shell 语法。
- 自动修改或删除 `mobile-test.config.cjs` 中的预制入口。
- 在命令预览阶段执行测试或探测命令副作用。
- App/Lynx App 执行页添加自定义命令；本次入口和命令预览聚焦小程序项目。
