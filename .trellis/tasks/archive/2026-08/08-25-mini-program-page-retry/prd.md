# 优化小程序页面重试状态

## Goal

让小程序页面重试精确执行用户选择的页面，并让来源运行的“正在重试”状态始终收敛到可操作的终态。

## Confirmed Facts

- `POST /api/tasks/:taskId/retry` 在请求携带 `caseRunIds` 时，从 Result Bundle 中映射 `caseIds`、`targetPages` 与页面参数；请求为空时创建 `scope: "task"` 的整任务重试。
- Runner SDK 会将 `retryOf.targetPages` 写入 `MTC_RETRY_TARGET_PAGES`。Fanli 的 `qa-mobile-test-console.cjs` 与项目 Provider 已优先消费该变量并通过 `--pages` 执行页面范围。
- 运行监控按重试链折叠为来源行；存在活动后代时，来源行和详情显示“正在重试”，并锁定重试、删除与保留操作。
- 当前来源行的活动状态依赖后代任务进入终态。运行超过 45 分钟时，页面持续显示“正在重试”，说明该运行缺少可靠的终态收敛路径或该路径未被触发。
- 现有接口、任务持久化、Runner、Result Bundle 和运行监控共同构成该功能的数据链路。

## Requirements

- 页面级重试请求保存且传递明确的页面范围；项目侧命令仅执行该范围中的页面。
- 整任务重试继续作为显式能力，页面级入口与整任务入口在界面上具有明确语义。
- 活动重试具有可观测的进度或超时保护；进程、Runner 或结果收集异常后，后代任务进入可诊断的终态，来源行恢复可操作状态。
- 停止重试后，来源行立即解除“正在重试”状态，并保留本次重试的诊断信息。
- 既有重试链的状态投影、成功结果合并、删除保护与历史任务加载保持兼容。

## Acceptance Criteria

- [ ] 单页面重试创建的任务具有 `scope: "cases"`，并保存该页面对应的 `caseRunIds`、`caseIds` 与 `targetPages`。
- [ ] Fanli 小程序页面重试命令收到单一页面范围时仅执行该页面；整任务重试仍执行来源任务保存的完整范围。
- [ ] 重试 Runner 超过约定时限或异常退出时，任务持久化为终态并记录可见原因；来源行不再持续显示“正在重试”。
- [ ] 用户停止活动重试后，来源行恢复重试、删除和保留操作。
- [ ] 服务端、Runner、Fanli 命令适配与 Web 运行监控具备覆盖页面范围和卡住恢复的回归测试。

## Out of Scope

- 改变流程测试的整流程重试语义。
- 重写既有 Result Bundle 的结果合并规则。

## Open Questions

- 页面级重试入口提供当前页面重试和全部失败页面重试；整任务入口保留完整范围重试。
