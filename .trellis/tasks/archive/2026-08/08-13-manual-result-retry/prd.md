# 测试结果模块复测与结果替换

## Goal

在测试结果页直接复测任意用例模块，并让当前模块展示最新一次复测结果，解决“自动判定通过但页面实际空白”时无法局部复核的问题。

## Requirements

- 终态任务的每个用例模块均提供“重新测试”，通过、失败和中断结果都可发起复测。
- 用户可选择重新测试单个用例；失败任务继续提供“重试全部失败用例”。
- 重试任务复用来源任务的测试定义、参数和运行目标，并遵守现有并发锁、参数校验和存储容量门禁。
- 每次复测生成新的 taskId、runId 和结果产物；复测完成后，来源结果页对应模块展示最新复测结果。
- 模块替换须覆盖状态、截图、页面诊断、接口记录、动作与断言、错误摘要和证据入口。
- 新任务记录直接来源 taskId/runId、重试范围、用例标识和重试次数，并向 Runner Plan 暴露相同 metadata。
- 项目适配器可消费用例范围实现定向复测；执行结果必须能稳定映射回来源模块。
- API 对未知任务、活动任务、未知用例、重复用例和忙碌运行目标返回明确错误。
- 结果页在操作期间将对应模块标为“重新测试中”并禁用重复提交；任务完成后自动刷新该模块。

## Acceptance Criteria

- [x] `POST /api/tasks/:taskId/retry` 可创建整任务或指定任意来源用例范围的新任务。
- [x] 新任务持久化 `retryOf` 来源信息，RunPlan metadata 携带同一份复测上下文。
- [x] 每个用例模块提供“重新测试”，失败结果总览保留批量重试入口。
- [x] 复测成功后自动聚焦最新任务并显示其最新结果和附件，旧任务仍可在运行历史入库保留。
- [x] 后端、API、前端交互和结果映射均有回归测试。
- [x] `pnpm lint`、`pnpm typecheck`、相关 Vitest 和构建检查通过。

## Notes

- 本任务实现 MTC 通用复测契约。项目级定向执行通过 Runner Plan metadata 扩展，由集成项目映射自身测试过滤参数。
- 自动吸收 Automator 瞬态错误仍由小程序项目测试层负责。

## Open Question

- 页面聚焦最新复测任务，只显示最新结果；旧任务和旧结果保留在运行历史，使用现有“长期保留/入库”操作保护产物。
