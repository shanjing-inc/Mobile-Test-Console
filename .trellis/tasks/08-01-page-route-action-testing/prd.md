# 简化页面自动化测试并完善路由参数与动作断言

## Goal

将 Mobile Test Console 的页面测试工作区收敛为可理解、可执行的页面测试流程：选择页面，填写页面打开所需的路由参数，验证页面正常打开，再选择页面按钮执行动作并验证响应结果。页面参数录制继续服务于路由参数发现和复用；页面测试以保存的路由画像、账号画像和业务脚本作为输入边界。

## What I already know

- 当前页面参数目录由 `packages/lynx/scripts/qa/qa-page-parameters.cjs` 生成。
- 页面参数全部通过 `huigou://lynx` 导航的 `params` 传递；原生层将参数转交给 Lynx 页面。
- 录制会话启动 Harmony 或 iOS QA App，读取宿主上报的 `lynx_page_parameters_observed` 事件，当前录制本身不记录按钮点击。
- 当前页面字段由上一轮实现根据 manifest 的 `routeParams`、源码静态读取点和动态读取标记自动推导，并非用户配置。
- 当前静态扫描只识别 `getPageParam("key")`；调用 `getPageParams()` 的页面只能标记为动态参数页，尚未追踪对象属性和后续用途。
- 仓库存在默认值、条件分支和多键回退：例如通知标题有默认值、邀请码只在存在时使用、商品 ID 可从 `q`、`id` 或 `goods.id` 多选一获取。
- 页面目标和断言目标已经存在，页面 runner 能执行动作并做 visible、text、selected、runtimeEvent 断言。
- 当前单页面回放覆盖了画像路由参数，但 `applyPageReplayOverrides` 会清空动作和断言，页面按钮测试尚未形成有效闭环。
- 当前页面详情同时展示捕获、历史、契约、输入、动作、断言和画像元数据，信息层次过深，截图中“参数契约”无法直接说明哪些字段是必要参数。

## Requirements

### 页面列表和页面详情

- 页面列表作为页面测试入口，选择页面后展示页面名称、bundle、路由参数状态和可测试动作数量；只有明确声明的必填字段才显示必填数量。
- 页面详情使用三个清晰区域：`页面参数列表`、`页面交互`、`测试结果`。
- `测试结果`固定放在页面详情顶部，测试失败、打开失败和缺少断言时在首屏展示结果与错误证据。
- `页面参数列表`的当前视图展示最近一条历史参数画像；历史画像按录制时间倒序展示，并提供完整应用、删除和直接回放操作。
- 当前路由参数为空时，页面编辑器和测试入口优先使用标记为默认的历史画像；没有默认画像时使用最近一组历史参数；当前页面没有历史画像时保留空草稿。
- 历史画像支持设置和取消默认标记，同一页面最多保留一组默认画像；默认选择按当前设备平台和环境重新计算。
- 保留搜索、全部页面总数和需参数数量；滚动容器继续独立滚动。

### 页面打开与路由参数

- 页面打开默认包含 `lynx_page_ready` 断言，明确表示页面完成打开并进入可测试状态。
- 从页面 `getPageParams()` 调用开始追踪参数对象、属性访问、别名和 `useRef(...).current`，生成页面实际读取的路由参数列表。
- 根据参数后续用途分类为“必填、可选、条件必填、动态未知”；默认值和纯条件功能参数归入可选或条件必填，多键回退记录为同一必填候选组。
- 使用录制画像的真实参数做逐项移除验证；参数移除后页面打开或基础内容断言失败时，确认该参数在当前场景为必填。
- 直接展示当前场景确认的必填路由参数，字段标记“必填”，保存或测试前缺失必填值时阻止执行并指出字段名。
- 可选路由参数单独折叠展示，字段标记“可选”，允许手动编辑和删除。
- 使用“录制参数”描述设备捕获结果；源码扫描生成参数建议和初步分类，移除验证生成当前场景的最终必填结论。
- 移除用户界面中的“参数契约”概念；页面测试只展示当前路由参数、参数来源和必填状态。
- 录制结果按页面展示路由、参数键和值，并提供“加入当前测试”；录制不会伪装成按钮动作录制。
- 保存的画像继续使用 `navigation.params` / `routeParams`，敏感值继续使用 `secretRef`。

### 页面交互与响应断言

- 页面动作覆盖页面目录中全部具有稳定 QA 语义标识的按钮目标。
- 缺少稳定 QA 语义标识的可点击节点在目录检查中显示“待补充测试目标”，不进入自动执行队列。
- QA sidecar 为按钮、输入框、Tab、列表项和可操作区块声明 `kind`、通用动作、平台动作能力和默认响应断言；控制台负责可视化编排，项目 provider 负责业务语义。
- 同一目标可声明 `platforms` / `platformActions`，控制台按测试设备过滤动作，保存和 runner 在设备启动前校验平台能力。
- 支持配置按钮动作：点击、输入、选择、提交和等待目标出现。页面交互由 QA 注入脚本与客户端协商执行，截图保留为运行证据，不作为交互定位步骤。
- 每个交互步骤至少包含一个预期响应断言，至少支持目标可见、文本包含、选中状态和运行时事件。
- 页面打开断言与交互后的响应断言在界面上分组展示，用户能看出每个按钮点击验证了什么。
- 保存画像时校验动作目标、动作类型、输入值、断言目标和运行时事件名称。
- 单页面测试必须保留已保存的路由参数、页面动作和结果断言，并传递给平台 runner 执行。
- 页面回放 provider 返回结构化步骤证据，控制台分别展示页面打开、动作通过数、断言通过数、缺少事件和逐步状态。

### 全量交互覆盖演进

- 当前源码约有 263 个 `bindtap` 站点、分布在 133 个文件；已声明 24 个语义目标、覆盖 6 个页面。后续以目录审计持续收敛“可点击站点 → QA 目标 → 交互用例 → 响应断言”的覆盖率。
- 每个交互目标采用独立基线执行：重新打开页面、恢复路由参数和账号画像、执行该目标的小步骤链、验证响应。该方式支持跳转、弹窗、登录、删除等会改变页面状态的动作。
- 输入加提交、选择加确认等强关联步骤可归入同一个交互用例；其它目标默认独立运行，避免前一个动作改变后续动作的前置状态。
- 项目 provider 可输出项目自定义目标类型、平台能力、默认断言和风险标签；控制台保持通用可视化编辑、运行调度和结果分析能力。
- 项目差异通过版本化 capability descriptor 接入：provider 可声明项目自定义动作、动作字段表单、敏感字段、支持平台、默认断言和结果证据类型；控制台依据 descriptor 生成可视化配置，并将执行委托给项目 provider。
- `tap`、`input`、`select`、`submit`、`waitFor` 继续作为内置通用动作；滑动、长按、原生 Bridge、项目专属手势等能力通过项目动作注册扩展，统一归一化为步骤状态、断言状态和证据引用。
- 覆盖审计输出页面总目标数、已注入数、已配置断言数、三端可执行数和待补充列表，并作为全页面套件的质量门禁。

### 测试入口

- “测试当前页面”执行当前页面画像，包含页面打开断言和已配置的交互步骤。
- 测试结果顶部提供参数画像选择器；选择历史画像时直接使用该画像回放，选择当前编辑参数时保存并回放当前草稿。
- 缺少必填路由参数、未选可用设备或画像未保存时给出明确提示。
- 页面测试结果显示页面打开、动作数量、断言数量和失败原因，便于判断是打开失败、动作失败还是响应断言失败。
- 全部页面套件提供测试账号选择；启动正式页面用例前先验证设备真实宿主存储中的会员会话。
- 会话失效时使用所选账号画像完成登录回放，并再次调用会员接口确认新会话可用；前置失败时停止正式页面用例并展示结构化原因。
- 登录前置只服务于页面运行环境准备，正式页面继续使用原路由、真实接口、页面动作和既有断言判定结果。
- 构建安装准备、登录探测和账号画像回放产物作为前置证据保存，不计入正式页面总数和通过率。

## Acceptance Criteria

- [x] 静态分析能从 `getPageParams()` 变量、属性访问、别名和 `useRef.current` 中提取页面实际使用的参数键。
- [x] 参数根据用途显示为必填、可选、条件必填或动态未知，多键回退能显示候选组。
- [x] 基于录制画像逐项移除参数后，页面打开和基础内容断言能确认当前场景的最终必填参数。
- [x] 页面详情能分别列出必填路由参数和可选路由参数，并明确说明必填来源与当前场景。
- [x] 选择录制结果可将该页面的路由参数填入当前测试，保存后画像中的 navigation.params 包含这些参数。
- [x] 页面缺少必填参数时无法保存或启动测试，错误消息列出缺失键。
- [x] 页面打开默认验证 `lynx_page_ready`，页面交互步骤可配置按钮动作和对应响应断言。
- [x] 页面目录中全部稳定 QA 语义按钮目标都能配置动作与响应断言，缺少语义标识的按钮显示待补充状态。
- [x] 页面目标支持语义类别、平台能力和 QA 默认断言；平台不兼容动作在保存或执行前被识别。
- [x] 页面动作保存时要求至少一个响应断言。
- [x] 单页面测试执行时不丢失画像中的 actions 和 assertions；测试 runner 收到完整动作与断言 JSON。
- [x] 单页面回放结果包含页面打开、动作、断言和逐步状态的结构化摘要。
- [x] 页面详情的主要操作在首屏可理解，捕获、历史、路由定义等辅助信息收纳在次级区域。
- [x] 现有页面列表筛选、总数、路由参数录制和历史画像回放能力保持可用。
- [x] 测试结果位于页面详情顶部，历史参数最近记录可见，历史画像支持完整应用、删除和测试画像选择。
- [x] 当前路由参数为空时优先使用页面默认历史画像，没有默认画像时回退到最近历史画像；手动编辑和录制捕获值保持优先级。
- [x] Mobile Test Console 与 Fanli QA 相关测试、Lint、TypeScript 检查通过。
- [x] 全部页面套件可选择与设备平台匹配且具备 `login` 能力的账号画像。
- [x] 全部页面套件先复用有效会话，会话失效时回放账号画像并复验会员接口。
- [x] 登录前置结果在控制台独立展示，准备阶段和前置阶段用例不进入 78 个正式页面统计。
- [ ] 建立全量可点击站点审计并将 78 个用户页面的待注入目标收敛为可执行交互用例。
- [ ] 将导航型、弹窗型和高风险动作拆分为独立基线用例并展示聚合结果。
- [ ] 建立版本化项目 capability descriptor，让自定义动作、字段表单、平台能力和结果证据可由项目 provider 注册并由控制台可视化呈现。

## Definition of Done

- 更新共享类型、provider/UI/API/runner 中必要的行为契约。
- 为必填参数校验、路由参数回放、动作与断言保留、UI 视图模型补充回归测试。
- 完成桌面与窄屏浏览器验证，确认页面测试入口和错误状态清晰。
- 完成质量检查和规格更新判断。

## Technical Approach

1. 用 TypeScript AST 分析替换当前正则扫描，从 `getPageParams()` / `getPageParam(key)` 追踪属性访问、局部别名、默认值、条件判断和多键回退。
2. 扩展字段模型表达必填、可选、条件必填、动态未知和候选组；保留 `required` 兼容字段供保存校验使用。
3. 使用录制画像驱动逐项移除测试，以 `lynx_page_ready` 和页面基础内容断言确认当前场景的必填集合。
4. 在共享模型中增加目标语义类别、平台动作能力和默认断言；保存时编译为当前平台 runner 可消费的动作与断言数组。
5. 修复 `applyPageReplayOverrides`，让页面回放保留画像 actions/assertions；无画像的纯页面打开测试仍使用默认 `lynx_page_ready`。
6. 将页面详情拆分为页面参数列表、页面交互、测试结果三个主块，录制控制与测试结果在顶部统一展示，历史资料作为辅助区域。
7. 页面 provider 从 runner 产物提取页面、动作和断言证据，控制台以步骤时间线呈现结果。
8. 下一阶段引入独立交互用例模型，默认在每个目标前重新打开页面并恢复输入画像。

## Decision (ADR-lite)

**Context**: 页面参数录制采集的是路由参数，当前 UI 将它和按钮动作、结果断言放在同一个复杂编辑面板；单页回放又清除了动作与断言。

**Decision**: 移除用户界面的“参数契约”概念。源码分析从 `getPageParams()` 的真实使用链路生成参数建议和初步分类，录制画像的逐项移除测试确认当前场景的必填集合；页面目录中全部稳定 QA 语义按钮目标纳入动作与响应断言配置，执行时保留完整画像数据。

**Consequences**: 页面测试具有确定性和可解释性；页面需要在目录中声明稳定目标，自动发现所有按钮和自动推断断言暂不纳入本任务。

## Out of Scope

- 本阶段完成目标目录、平台能力、断言和结果分析基础设施；263 个源码交互站点按页面分批接入后续覆盖任务。
- 坐标录制继续作为人工脚本证据，语义目标承担页面交互定位。
- 业务预期由 QA sidecar 或测试人员明确声明，平台保存和执行这些断言。
- 原生路由协议与 Harmony/iOS/Android 参数传递方式保持现状。
