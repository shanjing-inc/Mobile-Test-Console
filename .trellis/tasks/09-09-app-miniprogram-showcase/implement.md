- [x] 核对编码与时长，抽取概览和六个原尺寸帧。

- [x] 用户明确批准剪辑，已通过 task.py start 激活任务。

## 执行
1. 主会话读取相关规范，task.py start 激活本任务。
2. Trellis 实施子代理负责剪辑辅助脚本和媒体生成，按 research/showcase.md 定位真实素材；主会话负责双语 README 与复现文档。双方明确文件归属，保留他人改动。
3. 逐段审看原片，微调切点和遮挡位置；先生成短预览验证字幕、裁切与打码。
4. 生成 MP4、App GIF、微信历史结果 GIF 与封面，保存可复现命令。
5. 主会话接入 README.md、README.en.md 与 docs/showcase.md。
6. Trellis 检查子代理复核媒体信息、字幕真实性、遮挡覆盖、链接及代码改动；主会话完成媒体实际播放/关键帧检查。
7. 执行适合辅助脚本与文档的检查，核对打包清单和 git diff；按项目收尾规范记录进展。

## 验证
- ffprobe 检查 MP4 编码、分辨率、时长、像素格式；ffmpeg 解码成片检查错误。
- 检查 GIF 帧数、循环、时长与文件体积。
- 对所有保留镜头检查手机号、订单、设备名及标识的遮挡覆盖。
- 字幕检查：App 取消后的历史结果衔接、小程序历史结果标识及异常状态准确。
- 双语 README 图片、视频和说明链接有效，npm pack --dry-run --json 核对媒体未进入发布包。
- pnpm check:open-source；新增脚本执行对应语法/静态检查，项目要求的全量门禁按实际改动执行。

## 回滚
保留原始视频，独立输出媒体与文档；中间素材置于临时目录。发生处理问题时调整脚本重跑，原片保持完整。
