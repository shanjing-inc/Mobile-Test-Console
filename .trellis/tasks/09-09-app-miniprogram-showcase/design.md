# 实录剪辑设计

## 状态
用户已批准并完成剪辑实施；最终成片66秒，精确时间轴与复现参数见 docs/showcase.md。

## 素材
原始 MOV 长 118.385 秒，1920×972，约 59.94 fps，无音轨。ffmpeg 与 ffprobe 已安装。原片只读使用，处理副本与中间帧放独立临时目录。

## 规划时间轴与最终收敛
下表保留初选边界供审计。实施时压缩至66秒，接口使用90秒安全定格，微信使用108秒安全定格及113～118秒动态，绕开滚动中的敏感信息；最终逐镜头参数由 scripts/build-showcase.py 的 SHOTS 统一定义。

| 成片段落 | 源片时间 | 成片目标 | 字幕重点 |
| --- | --- | --- | --- |
| 标题 | 从实录选封面 | 3 秒 | App 与微信小程序，统一测试工作区 |
| App 选择与启动 | 0～16 秒 | 12 秒 | 选择 Android、iOS、HarmonyOS 设备与页面，启动测试 |
| 运行与取消 | 16～51 秒 | 7 秒 | 展示运行状态；本次启动后取消，接下来查看历史结果 |
| App 历史截图 | 52～79 秒 | 21 秒 | 历史测试结果，逐页查看截图与结果 |
| App 接口详情 | 80～93 秒 | 10 秒 | 关联接口请求与响应 |
| 微信历史结果 | 约 94～118.385 秒 | 19 秒 | 微信开发者工具运行目标与历史结果，查看异常页面 |
| 结束卡 | 文字卡 | 3 秒 | Mobile Test Console，README 提供启动方式 |

具体镜头优先取清晰停留、减少重复滚动；保留异常、未知与跳过的实际含义。微信段避免添加启动或当次通过的宣称。

## 两段 GIF
- App：从多设备启动、历史结果字幕与截图段组合为约 20～30 秒。
- 微信：取历史结果段约 15～20 秒，包含结果及截图浏览。
- 以约 1000～1280px 宽、8～12 fps 试编码，字幕和关键区域可读性优先，目标各小于 8 MB。

## 遮挡与画面
六个原尺寸检查帧中可见个人设备名、设备标识，60 秒帧包含登录手机号与订单信息；成片对同类区域跟随镜头遮挡。接口段保留功能结构，检查正文中出现的标识字段。局部放大结果区域，提高截图可读性。字幕用独立底栏，避免覆盖状态和操作按钮。

## 文件与兼容
媒体放 assets/showcase/，包括 app-demo.gif、wechat-results.gif、showcase.mp4 和封面。docs/showcase.md 记录源素材由用户提供、剪辑时间轴、参数与复现方式。生成脚本通过输入路径读取原片，仓库保存相对资源链接。MP4 使用 H.264、yuv420p、30fps、faststart，保持画面比例。媒体位于现有 npm 发布白名单之外，检查 README 在 GitHub 与 npm 上的链接差异。
