# 审核测试入口命令预览提交

## Goal

审核 MTC 测试入口命令预览提交及 SaaS 员工取件码排序入口的完整执行链路，修复确认的问题，并将通过审核的改动按仓库形成可追溯提交。

## Background

- MTC 功能代码已提交为 `88c8da4 feat(mtc): 支持自定义测试入口与命令预览`，任务归档和日志提交分别为 `40df8b3`、`d4f1b5e`。
- MTC 工作区仍有 `src/server/task-manager.ts`、`tests/task-manager.test.ts`、`tests/web-results.test.ts` 和 Android 构建报告改动，它们属于其他任务。
- SaaS 仓库已存在 `pnpm test:e2e:pickup-code-sort`、排序实现和测试改动；本轮新增 `mobile-test.config.cjs` 预制入口及配置回归测试。
- SaaS 的 `08-31-diagnose-page-matrix-e2e` 任务明确将取件码排序改动列为范围外，审核时需要保持两组改动边界清晰。

## Requirements

### R1. 审核 MTC 功能提交

- 审核 `88c8da4` 的共享契约、服务端预览与写入边界、前端状态机、目标选择保持、命令脱敏和过期响应处理。
- 重点验证选择入口即显示命令、单目标自动选择、用户取消后仍显示命令、启动后保留目标选择、多目标详情和 Runner 接管入口。
- 核查测试是否能在移除实现后失败，避免只验证源码字符串的空洞断言。
- 对机械且局部的问题直接修复；涉及公开契约或产品判断的问题先记录证据和建议。

### R2. 审核 SaaS 预制入口链路

- 从 `mobile-test.config.cjs` 追踪到 `package.json`、`run-e2e.mjs`、页面矩阵执行器、排序实现、fixture 和单元测试。
- 确认“员工取件码排序验证”业务名称、说明、能力声明和命令 `pnpm test:e2e:pickup-code-sort` 一致。
- 确认该入口在 MTC 执行页可见，选择后显示完整命令，运行目标状态符合 MTC 契约。
- 确认配置测试覆盖入口名称、目标和结构化命令。

### R3. 验证与提交

- MTC 执行 lint、类型检查、全量测试、构建、Schema、发布包和差异检查；记录现有开源检查误报。
- SaaS 对审核范围执行 lint、类型或单元测试，以及取件码排序相关的定向测试；需要真实外部环境的 E2E 记录可验证边界。
- 每个仓库按一个逻辑变更单元提交，不使用 amend，不推送远端。
- MTC 其他任务改动和 SaaS 页面矩阵诊断任务改动保持原状。

## Acceptance Criteria

- [x] 审核结果按严重级别列出，并带文件与行号证据；无问题时明确说明剩余风险。
- [x] MTC 命令预览、目标选择与启动后状态保持契约通过代码审查和回归测试。
- [x] SaaS 预制入口能够解析为 `pnpm test:e2e:pickup-code-sort`，且入口名称和用途完整展示。
- [x] 发现的局部问题完成修复并通过对应回归测试。
- [x] 两个仓库的相关质量门通过，环境型 E2E 限制有明确记录。
- [x] 通过审核的改动形成独立提交，其他任务改动未进入提交。
- [x] MTC 当前审核任务完成归档并记录工作提交。

## Out of Scope

- 重构 MTC 任务重试、结果合并或 Android 示例构建报告。
- 修复 SaaS 页面矩阵诊断任务中的邀请 code fixture 和开发者工具缓存问题。
- 扩展新的测试命令扫描、推荐或任意 shell 能力。
- 推送分支、创建 PR 或修改远端状态。
