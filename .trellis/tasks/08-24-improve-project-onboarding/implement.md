# 实施计划

1. 阅读 Web 层规范与 `ProjectCatalogWorkspace`、项目目录测试，确认现有设计系统、状态和接口。
2. 在项目卡片中建立接入进度与“当前下一步”视图，复用现有校验状态与预览/应用回调。
3. 将步骤详情改为新手可理解的任务描述；为运行环境和项目能力补充说明、帮助入口和可展开技术详情。
4. 为完成运行前检查的项目提供“运行首个测试”的后续入口，并保持现有工作区可用性逻辑。
5. 更新 CSS，确保桌面和窄屏的信息层级、按钮与折叠详情可读。
6. 扩展 `web-project-catalog` 测试覆盖通用 App、Lynx App 与小程序引导文案和动作。
7. 执行 `pnpm test -- web-project-catalog`、`pnpm typecheck`、`pnpm lint`；依据结果修复后复检。

## 风险点

- 不能修改 `ProjectOnboardingStep` 的服务端语义，避免影响目录持久化、运行前校验和已有集成测试。
- “运行首个测试”入口需复用已存在的工作区导航模型，避免绕过运行前检查。
- 外部文档路径需在开源仓库和打包产物中保持有效。
